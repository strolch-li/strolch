# Commit Messages

When committing changes, follow these guidelines:

- **Logically group changes**: Commits should be logically grouped, and thus multiple commits should be made if necessary
  by the changes made.
- Use the **Conventional Commit** format.
- **Prefix** the message with one of the following, depending on the context:
    - `[Fix]` -> for bug fixes
    - `[New]` -> for new features
    - `[Major]` -> for refactorings and other major/huge changes
    - `[Minor]` -> for minor changes which are not bug fixes
    - `[Project]` -> for changes to project specific files, which are not source code specific
    - **Note**: Don't use any other prefix than explicitly defined here.
- Start with a **short sentence in imperative form**, no more than **50 characters** long.
- Leave an **empty line** and continue with a more detailed explanation if needed.
- Write only **one sentence for the first part**, and **two or three sentences at most** for the detailed explanation.
- Use **bullet points** for multiple changes.
- **Avoid** overly verbose descriptions or unnecessary details.
- **Ignore formatting changes**, unless they are the only changes.
- **Ignore changes to import statements**, unless they are the only changes.
